# Code Review Report: Multi-mode Veles Implementation

**Branch:** `master`  
**Date:** 2026-07-20  
**Scope:** Multi-mode Veles planning extension

## Executive Summary

Review covered the multi-mode Veles planning extension branch in `av-opencode-plugins`. The change adds a full artifact approval pipeline, feature-manifest-based routing, headless dispatch metadata, and new Veles skills.

| Severity | Count |
|---|---|
| HIGH | 3 |
| MEDIUM | 11 |
| LOW | 4 |

**Top risks:**
1. **Dispatch authorization gap** — `dispatch_parallel`/`dispatch_background` do not enforce execution-time caller identity, allowing unauthorized subagent spawning.
2. **Sensitive routing incomplete** — `feature-manifest.ts` omits canonical control modules (`_shared`, `stribog`, `svarog`) from the sensitive-path list, so changes there can bypass Veles.
3. **Documentation-contract drift** — the documented approval argument and verified-content field names do not match the implemented tool schemas, breaking the approval handoff.

## Security Findings

### [HIGH] RV-001: Dispatch tools lack execution-time caller authorization gate

**ID:** RV-001  
**Location:** `src/modules/coordinator/dispatch.ts:135-145`, `src/modules/coordinator/index.ts:220-263,490-515`, `src/modules/plan/index.ts:76-90`  
**Category:** Security  
**CWE:** CWE-862  
**Effort:** medium

**Problem:**  
`dispatch_parallel` and `dispatch_background` derive only the caller's `mode` (primary/subagent/all). They never verify that the caller is `Perun - Coordinator` or another explicitly authorized agent. Because plugin-tool permission maps are documented as inert, the execution path is the only real enforcement surface.

**Impact:**  
An injected or unauthorized dispatch-capable agent can spawn subagents, including nested self-dispatch, leading to unbounded work and session exhaustion.

**Remediation:**  
Add an execution-time caller allowlist. Allow dispatch only from `Perun - Coordinator` and approved read-only Veles targets. Reject child/self-dispatch and propagate an immutable dispatch-depth + total-work budget.

---

### [MEDIUM] RV-004: TOCTOU symlink race enables out-of-scope artifact writes

**ID:** RV-004  
**Location:** `src/modules/coordinator/artifact-approval.ts:54, 80-91`  
**Category:** Security  
**CWE:** CWE-367, CWE-59  
**Effort:** medium

**Problem:**  
`approvePlanningArtifact` validates the artifact path, then later reopens and writes it by pathname. A concurrent worktree writer can swap the file or an ancestor for a symlink between validation and write.

**Impact:**  
The approval stamp and sidecar can be written to an out-of-scope file.

**Remediation:**  
Use descriptor-relative operations rooted in trusted directories, open with `O_NOFOLLOW` semantics, and verify the opened inode before writing.

---

### [MEDIUM] RV-005: Approval sidecar directory can redirect writes through a symlink

**ID:** RV-005  
**Location:** `src/modules/coordinator/artifact-approval.ts:60-63, 102-104`  
**Category:** Security  
**CWE:** CWE-59, CWE-73  
**Effort:** medium

**Problem:**  
`docs/.veles-approvals` is created and used without canonicalizing or checking each path component for symlinks.

**Impact:**  
A symlink at that location redirects lock files and sidecars outside the worktree.

**Remediation:**  
Canonicalize the approval directory beneath the worktree, `lstat` each path component, and reject symlinks.

---

### [MEDIUM] RV-006: Reservation and write operations race after path validation

**ID:** RV-006  
**Location:** `src/modules/plan/artifact-path.ts:99-102, 185-186, 223-232`  
**Category:** Security  
**CWE:** CWE-367, CWE-59  
**Effort:** medium

**Problem:**  
`resolveAllowedPath` validates parent paths, but `reserve()` and `write()` later open files by pathname. A concurrent actor can swap a parent directory or reserved file for a symlink.

**Impact:**  
Veles artifact creation or content can be redirected outside the intended directories.

**Remediation:**  
Retain trusted directory/file descriptors across validation and write; resolve child paths without symlink following and verify file identity before writing.

---

### [MEDIUM] RV-007: Approval sidecar identity differs from verified-read identity

**ID:** RV-007  
**Location:** `src/modules/coordinator/artifact-approval.ts:56-62, 100`  
**Category:** Security  
**CWE:** CWE-436  
**Effort:** easy

**Problem:**  
Approval hashes and stores a worktree-relative path for the sidecar filename, while `readVerifiedPlanningArtifact` hashes the absolute canonical path. The two sides therefore look for different sidecars.

**Impact:**  
Verified reads fail closed even for legitimately approved artifacts.

**Remediation:**  
Use one canonical artifact identity—prefer normalized worktree-relative paths—and use it consistently for sidecar filenames and `sidecar.path`.

---

### [MEDIUM] RV-008: Unescaped caller-controlled dispatch metadata reaches UI

**ID:** RV-008  
**Location:** `src/modules/coordinator/index.ts:183-232, 490-491`  
**Category:** Security  
**CWE:** CWE-116  
**Effort:** easy

**Problem:**  
Foreground/background task titles interpolate raw `agent` and `summary` values; task names and prompts are copied into metadata without neutralization.

**Impact:**  
A caller can inject control characters or misleading content into UI-rendered metadata.

**Remediation:**  
Apply `neutralizeUntrustedOutput()` to every metadata-bound string before calling `context.metadata()`.

## Architecture Findings

### [HIGH] RV-002: Sensitive routing policy omits canonical shared control modules

**ID:** RV-002  
**Location:** `src/modules/coordinator/feature-manifest.ts:106-128`  
**Category:** Architecture  
**Effort:** easy

**Problem:**  
`hasSensitivePath` is a hand-maintained deny-list. It still lists the obsolete `packages/skill-utils/src/session-identity.ts` and `coordinator-bash-policy.ts`, but omits their canonical replacements under `src/modules/_shared/`. It also omits `src/modules/stribog/` and `src/modules/svarog/`.

**Impact:**  
A manifest that changes only those control files can match the git-derived diff and be routed to `stribog`/`svarog` instead of the conservative `veles` planning path.

**Remediation:**  
Define sensitive roots centrally. At minimum add `src/modules/_shared/`, `src/modules/stribog/`, and `src/modules/svarog/`; prefer a policy module with table-driven tests.

```typescript
// Before
file === "packages/skill-utils/src/session-identity.ts" ||
file === "packages/skill-utils/src/coordinator-bash-policy.ts"

// After
const SENSITIVE_PATH_PREFIXES = [
  "src/modules/_shared/",
  "src/modules/stribog/",
  "src/modules/svarog/",
] as const;
return SENSITIVE_PATH_PREFIXES.some((prefix) => file.startsWith(prefix));
```

### [MEDIUM] RV-015: dispatch.ts is large and combines many responsibilities

**ID:** RV-015  
**Location:** `src/modules/coordinator/dispatch.ts` (~29 KB)  
**Category:** Architecture  
**Effort:** hard

**Problem:**  
Authorization, routing, task construction, worker-pool management, byte budgets, timeout overrides, scrubber lifecycle, and abort handling all live in one file.

**Impact:**  
The module is difficult to review and refactor; enforcement boundaries are easy to miss.

**Remediation:**  
Split into smaller modules: authorization gate, task builder, worker pool, budget enforcement, scrubber lifecycle.

---

### [LOW] RV-017: prompt.ts caches prompt forever without invalidation

**ID:** RV-017  
**Location:** `src/modules/plan/prompt.ts`  
**Category:** Architecture  
**Effort:** trivial

**Problem:**  
`let cached: string | undefined` is never invalidated. If `veles.md` changes during a long-running process, the updated prompt is invisible until plugin reload.

**Impact:**  
Stale prompt instructions after runtime edits.

**Remediation:**  
Either remove the cache or add a file-hash/mtime invalidation check.

## Performance Findings

### [MEDIUM] RV-010: feature-manifest git diff uses 10MB buffer that could OOM

**ID:** RV-010  
**Location:** `src/modules/coordinator/feature-manifest.ts`  
**Category:** Performance  
**Effort:** easy

**Problem:**  
`execFileGitRunner` uses `execFile` with the default 10 MB stdout buffer. A very large diff can exhaust it.

**Impact:**  
Classification fails or crashes on large changes. The fallback is `veles` (safe), but availability drops.

**Remediation:**  
Stream `git diff --name-only -z` with a child-process stream, or cap and paginate the output.

---

### [LOW] RV-018: artifact-approval uses synchronous fs calls

**ID:** RV-018  
**Location:** `src/modules/coordinator/artifact-approval.ts`  
**Category:** Performance  
**Effort:** medium

**Problem:**  
`openSync`, `readFileSync`, `writeFileSync`, and `rmSync` block the event loop.

**Impact:**  
Concurrent approvals or large file I/O can stall the process. Acceptable for rare approvals, but worth monitoring.

**Remediation:**  
Use async fs APIs with proper locking (e.g., `async-mutex`) if approval throughput grows.

### [MEDIUM] RV-009: Planning artifact tool names duplicated across runtime registration and prompt allow-list

**ID:** RV-009  
**Location:** `src/modules/plan/index.ts:31-34`  
**Category:** Maintainability  
**Effort:** trivial

**Problem:**  
`veles_reserve_planning_path` and `veles_write_reserved_planning_artifact` are hardcoded in both the runtime tool map and `allowed-tools.ts`.

**Impact:**

Export a canonical readonly tuple and derive both lists from it.

```typescript
  "veles_write_reserved_planning_artifact",
] as const;
```

## Cross-Verifier Composite Notes

- **Dispatch control plane lacks a trustworthy enforcement boundary.** The missing execution-time authorization gate (RV-001), unescaped metadata (RV-008), oversized `dispatch.ts` (RV-015), and incomplete headless-dispatch docs (RV-013) combine into a single high-risk surface. Centralize authorization, separate metadata escaping, and validate task schemas before dispatch.
- **Artifact approval is not end-to-end identity-safe.** The TOCTOU race (RV-004), symlink redirect (RV-005), reservation race (RV-006), and sidecar identity mismatch (RV-007) are compounded by documentation that names the wrong approval argument (RV-011) and verified-content field (RV-003). Fix the filesystem operations and the contracts together.

## Recommendations (Prioritized)

1. **Fix RV-001** — add execution-time caller authorization to `dispatch_parallel`/`dispatch_background`.
2. **Fix RV-002** — extend `feature-manifest.ts` sensitive paths to include `src/modules/_shared/`, `src/modules/stribog/`, `src/modules/svarog/`.
3. **Fix RV-003 and RV-011** — align `src/agents/perun.md` with actual tool schemas (`content`, `pre_approval_digest` or rename the schema).
4. **Fix RV-004, RV-005, RV-006, RV-007** — use descriptor-based, no-follow filesystem operations and a single canonical artifact identity.
5. **Fix RV-008** — neutralize dispatch metadata before it reaches the UI.
6. **Fix RV-012, RV-013, RV-014** — correct remaining documentation contract drift.
7. **Address RV-009, RV-015, RV-016, RV-017, RV-018** — smaller maintainability/performance improvements.
