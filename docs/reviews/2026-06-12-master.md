### [LOW] MAINT-003: Dist-sync coverage guard uses raw substring match — prefix false-positive

**ID:** MAINT-003
**Location:** `scripts/verify-dist-sync.mjs:180-181`
**Category:** Maintainability
**Effort:** easy
**Status:** [verified] (Challenger: confirmed LOW — real latent bug, harmless today)

**Problem:** The manifest-coverage guard checks each workspace is wired into the build via `buildDependents.includes(\`--filter ${ws.name}\`)`. Substring matching means a future package whose name is a **prefix** of an existing one (e.g. `@appverk/opencode-code`vs`@appverk/opencode-code-review`) would falsely pass coverage while its `dist/` is never rebuilt — the exact silent-drop this guard exists to catch. Harmless today (current names are mutually non-prefixing).

**Remediation:** Match the `--filter` value at a token boundary instead of a bare substring:

```js
const filterTokens = new Set(
  [...buildDependents.matchAll(/--filter\s+(\S+)/g)].map((m) => m[1]),
)
const builtAsDependent = filterTokens.has(ws.name)
```

This also naturally handles the quoted-glob form without special-casing.
