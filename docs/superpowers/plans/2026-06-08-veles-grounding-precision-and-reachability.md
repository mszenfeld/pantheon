## CRITICAL conventions for every task

- **Commits are hook-gated.** Prefix every commit with `AV_COMMIT_SKILL=1`. **NO push. NO co-author attribution of any kind.** Conventional Commits.
- **Run tests with `npx vitest run <path>`** — NOT `bun run test --`.
- **`toContain` is wrap-sensitive.** A substring that spans a Markdown source line-break never matches (see `tests/modules/plan/veles-prompt.test.ts:46-50`). **Paste each new rule so the asserted phrase sits on ONE source line — do not hard-wrap the asserted phrase.** Surrounding prose may wrap; the asserted span may not.
- **All three test files read `src/` directly** (`qa-plan-authoring.test.ts` and `test-plan-format.test.ts` read the SKILL.md; `veles-prompt.test.ts` calls `buildVelesPrompt()` which embeds `src/modules/plan/veles.md`). So a test passes as soon as `src` is edited — but you MUST still run `bun run build:root` and commit `dist/` with `src/`, or CI dist-sync fails.
- **Per-task loop:** write failing test → `npx vitest run <path>` (FAIL) → edit `src` → `npx vitest run <path>` (PASS) → `bun run build:root` → `bun run check` (full green) → commit `src` + `dist` + tests together.
- **Do not restate shipped prose.** Every edit below APPENDS to an existing bullet/sentence (located by a unique anchor you Read first) — never duplicate an existing rule.
- **Ordering matters (shared-section safety).** Apply tasks in order 1→2→3→4→5→6. Within a shared step, each task targets a DISTINCT bullet/paragraph; a fresh subagent Reads the file before editing, so earlier appends never collide with later ones.
- **No `docs/superpowers/` links** from any doc (AGENTS.md:251). **No per-review issue IDs** (SEC-/MAINT-…) in source or tests (AGENTS.md:262). The `L1`..`L5` lever tags are design labels for the commit subjects/test names only — fine to use, they are not per-review IDs.
